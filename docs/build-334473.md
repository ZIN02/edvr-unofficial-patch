## What changed in the game

Elite updated on 2026-10-20 from build 332841 (PE stamp `0x6A989634`, image
size `0x6409000`, SHA-256 `e6be8bbe…`) to build 334473 (`0x6ACD513D`,
`0x640C000`, `6891f70a…`; `VersionInfo.txt` 2026.10.13.334473). Code grew by
`0x2C50` bytes; `.rdata` and `.data` start `0x3000` higher. Both executables
are kept in `analysis/` (`EliteDangerous64.exe` is 332841,
`EliteDangerous64-334473.exe` is 334473), and the Ghidra project
`analysis/ghidra/ED334473` holds the analysed new build.

The update also rewrote 851 content-addressed data files. Of the two effects
archives, `Effects_` is unchanged since 2026-10-01 and `Effects2_` was
rewritten.

## How the move was measured

`tools/build_diff.py map` (added for this update) matches every code unit of
the old executable to the new one: byte-identical units anchor an in-order
walk, and every differing byte run must verify as a rel32, RIP-relative or
image-base displacement that lands on the mapped counterpart of its target.
Data addresses map by cross-reference voting plus a content check; vtables
are checked slot by slot. Of 301,451 old code units, 97% are IDENTICAL or
RELOC-ONLY.

All 87 functions that hold an EDVR-bound address map IDENTICAL (9) or
RELOC-ONLY (78); none changed. A second, independent mapper written for the
patch-note review agreed on every address both covered, and objdump of
named hooks on both sides matches once call and data targets are masked.
Walking callees seven deep from those functions finds one changed function,
`0x4313FC0` → `0x4316C80`, a keyframe step under job `0x4321810` that EDVR
only times.

Pins that had to be recomputed because they cover moved displacements: every
FNV body hash (the Oculus profile's eleven and the kinematic set),
`kUiPanelSiteBytes`, and the call-site pins at `0x42B42EA`, `0x42B4ED1`,
`0x43130A5`, `0x8D5337` and `0x4E70B6`. All 39 hook prologues are
byte-identical at their new addresses.

Terrain cull cover needed nothing: its signature scan finds the one call site
in 334473 on its own (site `0x4458D5D`, builder `0x4441580`).

## Ruled out

- ruled out: struct-offset changes in EDVR-bound code, because every bound
  function is IDENTICAL or RELOC-ONLY and RELOC-ONLY keeps immediates and
  displacements.
- ruled out: the light grid cache being affected by the hangar light fix,
  because the cache holds view-derived cluster geometry and its builder,
  refresh, copy and globals are unchanged apart from the move.
